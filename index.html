Troubleshooting cases

Cybersecurity case: SQL injection

What is the vulnerability?

User input is placed directly into a SQL statement, so the database reads that input as part of the command instead of as plain data.

How can it happen?

Through login forms, search boxes and URL parameters when queries are built by joining strings together with no validation.

What are the risks?

  • Login bypass
  • Exposure or loss of stored records
  • Modified or deleted data
  • Loss of user trust

How can developers prevent it?

  • Use parameterized queries or prepared statements
  • Validate and sanitize all input
  • Give the database account only the permissions it needs
Unsafe
"SELECT * FROM users WHERE name='" + name + "'"
Safe
"SELECT * FROM users WHERE name = ?"
// the value is sent separately

Security practices to implement

  • Hash stored passwords
  • Show generic error messages to users
  • Keep frameworks and database software updated
  • Test forms with invalid and unexpected input
